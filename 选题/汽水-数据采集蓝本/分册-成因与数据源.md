### 0.3 三条硬规则（证据链）

1. **结论不得先于证据**：每张归因卡至少 **2 条来源独立**的证据；不足 2 条 → 不进报告，只进「待验证假设池」。
2. **主客观互证**：任何成因判断至少一条**主观数据**（`SUR_*` / `OBS_*` / `INT_*`）+ 一条**客观数据**（`GOV_*`：政府公开、招标采购、预算、法规），或两条不同类型的一手数据。只有主观证据的条目必须标注「仅主观证据，未与客观数据互证」。
3. **可回溯**：每条证据写清「`SRC_ID` / 字段 / 记录 ID / 获取日期 / 获取人」；AI 生成的每条归因须标 `AI_METHOD` 与 `REVIEW_STATUS`。

### 0.4 合法性总则（采集前先看这几条）

1. **政府信息以主动公开为先**：《政府信息公开条例》（国务院令第 711 号，2019 修订）确立「公开为常态、不公开为例外」；能主动下载的不走依申请，能依申请的不找人打听。
2. **个人信息最小化**：不采集姓名、手机号、身份证号、人脸；访谈录音前先告知用途并征得同意（`INT_CONSENT_YN`）；观察只做计数与行为类型，不拍正脸。
3. **平台协议优先于爬虫能力**：先查开放许可与 `robots.txt`，不绕验证码、不破频率限制、不转售数据。
4. **12345 类工单不做批量抓取**：只用①公开留言与官方公开案例、②依申请公开、③访谈街道/公园管理人员（`INT_G_*`）；不做用户身份层面处理。
5. **商业平台文本（点评/小红书等）是最高风险源**：仅小样本主题统计，不引个体原文+账号，视为「氛围线索」而非证据主体。
6. **AI 使用留痕**：AI 参与标注、评分、写作均记日志（模型、提示词要点、输入样本量、人工复核比例），对应比赛「AI 使用说明」附录（分册 C 第 13 章）。

## 2. 第 8 章　客观数据源清单

### 8.0 取数总原则

1. **层级跟着地理边界走**：若定「大学城周边 6–10 个空间」→ 取到 **区 + 街道 + 单点**；若定「深圳全城抽样」→ 取到 **市 + 区**。【待拍板 PB1 = 分册 A P1】
2. **三档获取方式**（成本从低到高）：① 平台直接下载/API → ② 网页检索 + 人工摘录建档（附截图与 URL） → ③ 依申请公开（法定 20 个工作日内答复；**赶不上 10-24 则只进 v2**）。
3. **每条源必须记 6 要素**：数据内容 / 来源层级 / 获取方式 / 合法性限制 / 更新频率 / 拟支撑成因；另记获取日期、URL 或文件名、获取人 → 进 `数据源登记表`（XLSX 一源一行）。
4. **口径优先于数量**：同一指标只用一个口径来源（如公园绿地面积统一用统计年鉴），冲突时以官方统计口径为准并在 `GOV_NOTE` 写差异。
5. **渠道 ≠ 数据**：第 2 章的 `Sxx` 是**渠道编号**；从渠道取到的每个指标登记为一条 `GOV_ID` 记录（对应关系见 8.9）。

### 8.9 落到 D5 客观数据表（`GOV_*`）

每条渠道取到的**每个指标**登记为一行 `GOV_ID`，与分册 C §10.5 对齐：

| `GOV_*` 字段 | 来源 | 填写规则 |
|---|---|---|
| `GOV_ID` | 分册 C 规则 | `GOV-<指标码>-<年份>`，如 `GOV-PARKAREA-2025` |
| `GOV_METRIC` | 指标名 | 与 `SITE_*`/`OBS_*` 口径可对照，如「公园绿地面积」「市政基础设施投资额」「园林绿化养护经费」 |
| `GOV_VALUE` / `GOV_UNIT` / `GOV_YEAR` / `GOV_GEO` | 渠道原文 | 单位统一（㎡/元/个）；`GOV_YEAR` 是**统计口径年**，不是发布年；`GOV_GEO` 写到「深圳市南山区」「西丽街道」 |
| `GOV_SRC_URL` / `GOV_PUBLISHER` | 必填 | 渠道编号同时记进 `数据源登记表`（S 编号），实现「渠道 ↔ 数据」双向可查 |
| `GOV_CAUSE_CODE` | 本分册第 1 章 | 填 `CAUSE_1`–`CAUSE_5`，一指标多成因用 `_1`/`_2` 列 |
| `GOV_NOTE` | 口径说明 | 是否含道路/临时绿地、是否含市级统管公园、是否含在建项目 |

> 例：`GOV-CITYGREEN-2025` 取自 S02，`GOV_GEO=深圳市`，`GOV_CAUSE_CODE=CAUSE_2`，`GOV_NOTE=统计年鉴口径，含建成区绿地`。

### 9.3 环节 3：AI 归因规范

#### 9.3.1 方法 A｜文本主题归类（`AI_METHOD = TEXT_TOPIC`）

| 项 | 规范 |
|---|---|
| 输入 | 访谈转写与摘录（`INT_QUOTE`、`INT_EVENT`）、`SUR_OPEN` 开放题、S06/S20 公开诉求文本 |
| 编码本 | 预定义 `CAUSE_1`–`CAUSE_5` + 每类 3–6 个子标签（如 `CAUSE_1-开放时间`、`CAUSE_1-管理约束`、`CAUSE_3-遮阴`、`CAUSE_3-绕行`），并以 `L1`–`L10` 辅助；允许 `CAUSE_0-其他` 与「无法归类」 |
| 流程 | ① 人工试标 30 条定子标签边界 → ② 大模型初标 → ③ 两人独立标 30 条 → 一致性（Cohen's κ ≥0.6 可用、≥0.8 良好；分册 C 要求编码一致率 ≥80%）→ ④ 冲突仲裁并修订编码本 → ⑤ 全量标注 → ⑥ 抽 20% 人工复核 |
| 输出 | 每空间每成因的子标签频次 + 3–5 条**脱敏**引文 + 一致性系数 |
| 禁止 | 用 AI 替代全部人工标注；把 AI 归纳直接写成报告结论；引用含个人身份信息的原文 |

#### 9.3.2 方法 B｜相关分析（`AI_METHOD = CORR`）

| 项 | 规范 |
|---|---|
| 输入 | `OBS_*` 观察表、`SITE_*` 空间清单、`GOV_*` 客观指标 |
| 方法 | 空间数 6–10 属小样本：主用 **Spearman 秩相关**；群体差异用 Mann-Whitney U / Kruskal-Wallis；空间数扩到 ≥20 再考虑分层回归 |
| 控制变量 | `OBS_TIME_SLOT`、`OBS_WEATHER`、`OBS_DAY_TYPE`、考试周（写进 `OBS_NOTE`/备注） |
| 输出 | 相关矩阵 + 每对相关的 **n、p、效应量**；文字统一写「相关方向/强度/样本量」，**不写「证明/导致」** |
| 禁止 | 小样本下做因果断言；多重比较不校正；把区级生态相关当个体层结论 |

#### 9.3.3 方法 C｜可解释评分（`AI_METHOD = EXPLAIN_SCORE`）

**双轨缺口（两条都要，别混）**

```
① 感知缺口（分册 A §3.4 已定，沿用）：GAP_k = SUR_IMP_k − SUR_SAT_k      （0–5）
② 客观缺口（本分册新增，做空间间比较）：
   SCORE_DEMAND_K(g) = mean(SUR_IMP_k | 群体 g) / 5                        （0–1）
   SCORE_SUPPLY_K(s) = 客观供给归一（0–1），对应关系见下表
   SCORE_GAP_K(s,g)  = SCORE_DEMAND_K(g) − SCORE_SUPPLY_K(s)              （0–1）
③ 加权总缺口：SCORE_GAP_total(s,g) = Σ_k WEIGHT_K · SCORE_GAP_K(s,g)
```

| 指标 k | 需求变量（A 权威） | 客观供给 `SCORE_SUPPLY_K` | 归一化 |
|---|---|---|---|
| 座位 | `SUR_IMP_SEAT` | `OBS_OCC_RATE`（0–1，直接可用）+ `SITE_SEAT_CNT` | 原生 0–1 |
| 遮阴 | `SUR_IMP_SHADE` | `SITE_SHADE_CODE`/`SITE_SHADE_PCT`，或 `OBS_SHADE_CODE`/`OBS_SHADE_PCT` | `PCT` ÷100；`CODE` 减 1 后 ÷4；两版并列 |
| 免费开放 | `SUR_IMP_FREE` | `SITE_ENTRY_FREE_YN` | 原生 0–1 |
| 空调（选填） | `SUR_IMP_AC` | `OBS_AC_CODE`（1 无～3 全覆盖） | 减 1 后 ÷2；`-98` 剔除 |
| 安静（选填） | `SUR_IMP_QUIET` | `OBS_NOISE_SCORE` | ÷5 |
| 整洁（选填） | `SUR_IMP_CLEAN` | `OBS_CLEAN_SCORE` | ÷5 |

| 项 | 规范 |
|---|---|
| 权重 `WEIGHT_K` | **【待拍板 PB4】** 方案 A：`SUR_IMP_*` 均值归一；方案 B：AHP 专家打分 + 问卷校准。两种并列展示差异 |
| 敏感性 | 权重 ±20% 扰动 + 三种备选权重，输出「排序是否稳定」；排序翻转必须标注 |
| 输出 | 空间×成因得分矩阵、改善优先级排序、边际收益排序（每提升 1 单位供给的缺口缩减量）、雷达图；`GAP_*` 与 `SCORE_GAP_*` 并排（差异作为线索保留，不解释成结论） |
| 归因粒度 | **空间级**（每空间成因剖面）/ **群体级**（`SUR_ROLE`、`SUR_AGE_GRP4`、`SUR_OCC`、`SUR_DISTRICT`）/ **成因级**（CAUSE_1–5 权重）→ 三维交叉热力表 |
| 禁止 | 只给总分不解释分项；隐藏权重来源；输出「最优方案」不标不确定性；用区级统计替代单点供给分 |

#### 9.3.4 归因卡模版（`AC-{SITE_ID}-{CAUSE_CODE}`，最小证据单元）

| 字段 | 要求 |
|---|---|
| 空间/群体/时段 | `SITE_ID` + 群体（`SUR_ROLE`/`INT_SUBJ` 或 `OBS_GROUP_MIX`）+ `OBS_TIME_SLOT` |
| 成因 | `CAUSE_CODE`（1–5）+ 子标签（可带 L 码） |
| 结论句（一句话） | 只描述「数据呈现的差异」，不写因果 |

#### 9.3.5 置信度判定与「交付门」

| 置信度 | 判定规则 |
|---|---|
| **高** | ≥2 类**来源独立**证据（如问卷 + 招标公告），方向一致，且样本量/记录数达标 |
| **中** | 2 类证据但方向不完全一致，或 1 类多源（如同一对象 3 位受访者） |
| **低** | 单一来源，或仅 AI 推断未复核 |

**交付门（不满足不得进对外报告）**：① 置信度 ≥中；② 有反证行；③ 证据可回溯到记录 ID；④ 已人工签发；⑤ 客观数据缺失时明确标注「仅主观证据」。

#### 9.3.6 人工复核与留痕

- AI 输出**一律**为「分析辅助」，归因卡由人签发，签发人对结论负责。
- 抽样复核比例 ≥20%，且每个成因至少覆盖 1 张卡。
- 记 `AI 使用日志`（模型/版本、任务类型、输入样本量、提示词要点、人工修订处、复核比例），按分册 C 第 13 章格式，直接服务比赛「AI 使用说明」附录。

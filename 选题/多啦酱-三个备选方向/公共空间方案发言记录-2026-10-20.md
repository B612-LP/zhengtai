## 一、问卷：先做一轮"改进偏好"的初步调查

- 让受访者填问卷，先请他们自己想：对这类公共空间有什么**改进偏好**。
- 这**不是**我们真正需要的结论，也**不是**最终得出的改进偏好，只是一次**初步调查**，归入研究报告的一部分。

## 二、公共空间的数据库（调查）

### 1. 选定具体地点

- 选 **6–10 个以内**。
- 尽量**覆盖不同种类**，不要都挑同一种。
- 类型可以是：公共绿地 / 公园；街道休息区；公共交通站点附近。

### 2. 数据获取方式

- 能从线上拿到的，就**线上找**。
- 线上找不到的，**线下去观察**。

### 3. 线下观察重点

- (a) **设施情况**：例如这个地方有多少座椅。
- (b) **硬件条件**：整体的遮光情况、空调能力如何。
- (c) **入座率**：整体人气如何，人来得多不多，还是像"摆设"一样没人（设施摆着没人用）。

### 4. 空间信息清单（List）

每个空间按下列字段建档：

| 字段 | 内容要求 |
|---|---|
| (a) 地点编号 | — |
| (b) 名称及类型 | 注明属于哪一类（公园 / 街道休息区 / 交通站点等） |
| (c) 座椅情况 | — |
| (d) 遮阴情况 | — |
| (e) 开放时间 | — |
| (f) 步行可达性 | 分别是什么交通方式 |
| (g) 主要限制 | — |
| (h) 信息来源 | — |
| (i) 核实日期 | 即调查、核实该条数据的日期 |

> 这份清单将作为后续 **AI 辅助交互系统的基建**。

### 5. 线下访谈注意事项

- 最大风险：**访谈内容与问卷重叠**。例如只问"平常待在什么地方""觉得怎么样"，一旦重叠，访谈就没有意义。
- 分工认识：**问卷**是对 200 多人取不同结论、**发现规律**；**访谈**是在问卷结果的基础上**理解原因**。所以访谈问题要更具体。
  1. **避免与问卷重叠**：不要问"你觉得座位够吗"——这已经和问卷里"座位数量"的需求测查重叠了。
  2. **提问要具体化**：例："你最近一次想坐下来，但坐一会儿就走了、没有长时间停留，是什么时候？当时有没有想再找另外一个地方坐？"
  3. **挖掘深层原因**：例："如果有什么样的条件可能会把你挽留下来？""为什么要坐一会儿就离开了？""为什么有的地方明明座位特别多，但坐的人却很少？""为什么有的人宁愿去商场，也不愿意在这种场合待着？"

## 三、供需分配与研究报告

### 1. 研究报告分三部分

1. **描述性统计**：把问卷和调研结果先列出来，最基础的，用 Excel 或 Python 做。
2. **分析不同群体的需求差异**：比如学生更倾向于去什么样的地方；或者在某个地方，哪些座椅更有吸引力、有更多人坐。例：图书馆有很多种座位，那种有**私人隔断**的往往最先满。
3. **供需错配与改善优先级**：先找出供需错配是什么样——座椅够不够、遮阴够不够、空调够不够；再判断**最优先要改善的是哪一个**。

### 2. 供需匹配分析

- 指标暂定三个：**座位、遮阴、免费开放**。
- 把三者的**重要性按分数**列出来。分数来源：问卷里问用户"更需要哪一种公共空间"，**0–5 分**自己打分（像外卖里给骑手打分那样）。
- 后面再写上对应空间的**供给情况**，分析结果争取**简化**，最后给出**改善建议**。

## 四、AI 演示系统

1. **背景界面**：以大地图为背景（类似谷歌地图、高德地图），列出学校周围、或整个深圳的各个公共场所地点。
2. **地点信息交互**：把城市当作一个店铺来展示。我们调查了十几个地方，鼠标点开某个地点就弹出对应信息框——这种"点哪出哪"的交互能体现虚拟性。
3. **青年需求画像**：把问卷统计结果做成需求画像直接放进系统，比如展示**哪个群体去了哪个地方**，更直观。

- 设计动机：研究报告太数据化，有人没耐心看完；做成系统里的统计后，用户可以**选择性查找**，减少他们的工作。

## 五、AI 框架：先原型，后数据

- 先做**原型框架（蓝本）**：**不带任何数据**，先把页面结构、交互逻辑、视觉设计做出来（相当于一个独立站）。
- 等界面交互、设计、结构都 OK 了，**再把数据放进去**。
- 形态选择：**网站**最省事（比小程序 / 软件简单、省钱、不耗本地资源），做成**独立站**。
